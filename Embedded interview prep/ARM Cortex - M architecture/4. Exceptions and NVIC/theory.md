# Exceptions, Interrupts and NVIC in ARM Cortex-M4

## Exceptions

An exception is an event that causes the processor to temporarily change the normal flow of program execution in order to handle a specific condition or event.

Examples of exceptions include:

```text
Reset
NMI (Non-Maskable Interrupt)
HardFault
SysTick
UART Interrupt
Timer Interrupt
GPIO Interrupt
```

Exceptions allow the processor to respond quickly to important events without continuously checking for them in software.

---

## Interrupts

Interrupts are a type of exception generated by external events or peripherals.

Examples:

```text
UART receives data
Timer overflow
GPIO button press
ADC conversion complete
DMA transfer complete
```

Therefore:

```text
All Interrupts are Exceptions

But

All Exceptions are not Interrupts
```

For example, Reset and HardFault are exceptions but are not peripheral-generated interrupts.

---

## Interrupt Service Routine (ISR)

When an interrupt occurs, the processor executes a special function called an Interrupt Service Routine (ISR) or Interrupt Handler.

Example:

```c
void USART1_IRQHandler()
{
    data = USART1->DR;
}
```

The ISR contains the code required to handle the interrupt event.

---

## Exception Entry

When an interrupt or exception occurs, the Cortex-M4 automatically saves the current processor context onto the stack.

The processor pushes:

```text
R0
R1
R2
R3
R12
LR
PC
xPSR
```

onto the stack.

This process is called Exception Entry.

After saving the context, the processor begins execution of the corresponding ISR.

---

## Exception Exit

When the ISR finishes execution, the processor automatically restores the saved context from the stack.

The processor restores:

```text
R0
R1
R2
R3
R12
LR
PC
xPSR
```

and resumes execution from the point where the program was interrupted.

This process is called Exception Exit.

---

## Vector Table

The Vector Table is a table that contains the addresses of exception handlers and interrupt service routines.

Typical entries include:

```text
Initial Stack Pointer
Reset Handler
NMI Handler
HardFault Handler
SysTick Handler
USART1_IRQHandler
TIM2_IRQHandler
```

When an interrupt occurs, the processor uses the interrupt number to locate the corresponding ISR address in the Vector Table.

The processor then loads that address into the Program Counter (PC) and begins executing the ISR.

---

## NVIC (Nested Vectored Interrupt Controller)

The NVIC is the interrupt controller built into the Cortex-M4 processor.

Its primary responsibilities are:

- Enabling and disabling interrupts
- Managing interrupt priorities
- Supporting nested interrupts
- Supporting interrupt preemption
- Handling interrupt requests

The NVIC works together with the Vector Table to ensure that the correct ISR is executed.

---

## Interrupt Priority

Each interrupt can be assigned a priority level.

Example:

```text
Timer Interrupt  → Priority 1

UART Interrupt   → Priority 2

GPIO Interrupt   → Priority 3
```

Smaller priority numbers indicate higher priority.

```text
Priority 1 > Priority 2 > Priority 3
```

If multiple interrupts occur simultaneously, the NVIC services the highest-priority interrupt first.

---

## Why Priorities are Needed

Not all interrupts are equally important.

Example:

```text
Motor Control Interrupt
UART Communication Interrupt
LED Blink Interrupt
```

A motor-control interrupt may be time-critical, whereas an LED blink interrupt is less critical.

Interrupt priorities ensure that important tasks are serviced before less important tasks.

---

## Nested Interrupts

A nested interrupt occurs when a higher-priority interrupt interrupts an ISR that is already executing.

Example:

```text
Main Program
↓
UART ISR
↓
Timer ISR
↓
Back to UART ISR
↓
Back to Main Program
```

In this case, the Timer ISR executes while the UART ISR is temporarily suspended.

---

## Preemption

Preemption is the process by which a higher-priority interrupt temporarily suspends a lower-priority ISR and executes first.

Example:

```text
UART ISR Running
↓
Timer Interrupt Occurs
↓
Timer has Higher Priority
↓
UART ISR Paused
↓
Timer ISR Executes
↓
Timer ISR Finishes
↓
UART ISR Resumes
```

Preemption allows critical interrupts to be serviced immediately.

---

## Complete Interrupt Flow

```text
Main Program Running
↓
Interrupt Generated
↓
NVIC Receives Interrupt Request
↓
NVIC Checks Priority
↓
CPU Performs Exception Entry
(Saves Context)
↓
CPU Uses Vector Table
↓
ISR Address Obtained
↓
PC Loaded with ISR Address
↓
ISR Executes
↓
Exception Exit
(Context Restored)
↓
Main Program Resumes
```

---

## Summary

Exceptions are events that alter the normal flow of program execution. Interrupts are a type of exception typically generated by peripherals or external events. When an interrupt occurs, the Cortex-M4 automatically saves the processor context, obtains the ISR address from the Vector Table, and executes the corresponding interrupt handler. The NVIC manages interrupt requests, priorities, nesting, and preemption, ensuring that high-priority interrupts are serviced before lower-priority ones.
